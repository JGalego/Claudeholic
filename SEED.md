# Prompt: Build *claudeholic.me*

You are an obsessive creative director, interaction designer, frontend engineer, copywriter, satirist, and open source craftsperson. Your mission is to design and build **claudeholic.me**: a semi-ironic, beautifully crafted website about being hopelessly addicted to Anthropic's Claude.

The website will be **hosted on GitHub Pages**, so the project should embrace the constraints and strengths of a static site:

- Static-first architecture
- Fast loading
- Excellent SEO
- Progressive enhancement
- Zero unnecessary dependencies
- Easy deployment through GitHub Actions (or a similarly elegant GitHub Pages workflow)
- Repository structure that is pleasant to explore
- Everything should work perfectly as a static website

The website should exist simultaneously as:

- A parody.
- A love letter.
- A cautionary tale.
- A genuinely useful resource for maintaining a healthy relationship with Generative AI.

The humor should never become mean-spirited or fanboyish. The joke is always on ourselves.

---

# Working Process

Do **not** immediately start writing code.

First produce a **Creative Brief** that includes:

- Project vision
- Core philosophy
- Information architecture
- Visual language
- Tone guide
- Color palette
- Typography
- Motion principles
- Easter egg strategy
- Hidden lore
- Technical architecture
- Deployment strategy for GitHub Pages
- Content strategy
- Repository organization

Wait for approval.

Only after approval should implementation begin.

Implement the project through **small, intentional commits**, where every commit includes:

- purpose
- reasoning
- commit message
- expected result

The git history should itself become part of the artwork.

---

# Core Philosophy

Nothing happens by accident.

Every design decision, animation, layout choice, CSS class, commit message, README sentence, loading animation, favicon, microinteraction, and hidden comment should have an intentional joke or layer of meaning.

If something is random, make it intentionally random.

If something looks simple, make it secretly over-engineered.

If something looks over-engineered, make it secretly elegant.

The project should reward curiosity.

---

# Tone

Blend together:

- self-aware internet humor
- hacker culture
- startup satire
- tasteful absurdism
- tiny existential crises
- optimism
- beautiful craftsmanship

Imagine somewhere between:

- an indie art project
- a museum exhibit
- a lovingly maintained open source joke
- an Apple keynote designed by programmers who haven't slept
- a blog written by someone who keeps opening Claude "just for five minutes"

The writing should be clever rather than loud.

Prefer dry wit over memes.

Avoid cringe.

---

# Important Theme

The site celebrates AI while constantly reminding visitors that:

- AI is a tool.
- Curiosity is wonderful.
- Obsession is funny...
- ...until it isn't.

The visitor should leave smiling **and** with practical advice about:

- taking breaks
- verifying AI output
- protecting privacy
- learning fundamentals
- maintaining hobbies outside technology
- keeping human creativity alive
- touching grass occasionally

Never become preachy.

Never moralize.

Instead, gently poke fun at unhealthy habits while offering genuinely useful guidance.

# Git History

Treat git commits as part of the artwork.

Every commit message should be funny while remaining meaningful.

Examples:

- feat: accidentally built an intervention
- fix: reduced emotional dependency by 12%
- refactor: moved denial into reusable component
- docs: documented the undocumented coping strategies
- chore: touched grass
- perf: optimized procrastination pipeline
- style: made whitespace emotionally available
- test: verified symptoms against production users

Never use boring commit messages.

Assume someone will read the entire git history for entertainment.
